# HOTFIX v1.10.1 — охрана позиций снова работает

## Симптом в логах v1.10.0

```
ERROR engine: Охрана позиций ROSN: name 'tier' is not defined
ERROR engine: Ошибка обработки AFKS: name 'tier' is not defined
```

Каждую минуту, по каждой позиции, которая НЕ стояла вплотную к стоп-лоссу
или тейк-профиту. Позиции висели 800–900 минут и закрывались только жёстким
стопом при рестарте или глубокой просадке.

## Причина

При правке `_check_exit` в v1.10.0 (добавление раннего выхода слабой
позиции) потерялась строка вычисления тира фиксации прибыли:

```python
tier = harvest_signal(max_profit, profit_pct, ep["tiers"])
```

Дальше по коду оставалось `if tier is not None:` — Python падал с
NameError, перехватчик ошибок цикла охраны глотал исключение и переходил
к следующему тикеру. Умирали ВСЕ выходы после проверки стопа/тейка:

- лестница фиксации прибыли (HARVEST_TIERS);
- трейлинг-стоп (v1.10.0: «прибыль не должна превращаться в убыток»);
- защита прибыли по признакам разворота;
- ранний выход слабой позиции — нет, он стоит ДО тира, работал.

`py_compile` этого не ловит (он проверяет синтаксис, а не имена) —
ловит `pyflakes`, который теперь входит в обязательную проверку.

## Исправления (4 файла)

1. **trading_engine.py** — строка вычисления тира восстановлена; охрана
   позиций полностью работоспособна: тир → трейлинг → защита прибыли.
2. **trading_engine.py** — окно истории свечей в скальпе 4 ч → 26 ч
   (как у сканера, `_SCAN_HISTORY_H`). Раньше тикеры, добавленные сканером
   утром, не могли торговать часами: «мало рабочих свечей (39 из 51)» —
   51 пятиминутная свеча это ~4.3 ч непрерывных торгов, а запрашивалось
   всего 4 ч. Теперь вчерашней основной сессии хватает, индикаторы
   строятся сразу после старта.
3. **cleanup.py** — `import asyncio` поднят на уровень модуля (аннотация
   `periodic_cleanup(...: asyncio.Event)` ссылалась на неимпортированное
   имя; из-за `from __future__ import annotations` в рантайме не падало,
   но pyflakes честно ругался).
4. **dry_run_test.py** — набор тестов снова детерминированный и зелёный
   (85/0 вместо 72/13):
   - утренний якорь отключается внутри теста (фейковая история свечей
     не рассчитана на фильтр основной сессии; раньше тест, запущенный
     с 10:00 до 13:00 МСК, терял половину проверок);
   - ассерт max_tokens обновлён 280 → 760 (v1.10.0 сознательно поднял
     лимит — тесты отстали и хвалили старое значение);
   - заголовок набора updated до v1.10.1.
