# MOEX Trading Bot v1.7.2 (T-Invest API + Groq AI + Telegram)

Production-ready торговый бот для Московской биржи, спроектированный под VPS
с **1 ГБ ОЗУ** и **15 ГБ диска**. Работает через официальный T-Invest API,
использует **бесплатный** Groq API (трейдер-LLM, сентимент новостей, аудит
логов, вердикты сканера) и управляется из Telegram.

Новое в v1.7.2:
- **ПАМЯТЬ «ЧЕМ ТОРГУЕМ» (главное)**: после рестарта бот СРАЗУ подключает
  все известные тикеры (список бумаг + открытые позиции) из вселенной TQBR.
  Раньше после перезапуска в кэше оставались только тикеры из .env: бумаги,
  добавленные на ходу (автоподключение сканера, /watch, ручные покупки),
  ловили «не в кэше инструментов», их позиции оставались без стопов/тейков,
  пока сканер случайно не встречал бумагу среди кандидатов. Теперь позиция
  под охраной с первой минуты (в логе: «Помню, чем торгуем (N бумаг...)»);
- **ПРОГНОЗ ЦЕНЫ**: новый модуль `predictor.py` - детерминированный
  ансамбль: инерция движения (моментум) + возврат к средней (z-score,
  half-life) + режим рынка (variance ratio) + конус 80% из EWMA-волатильности
  (lambda=0.94, RiskMetrics). Прогноз двумя путями:
  1) команда **/predict [ТИКЕР] [1-24 ч]** - график (факт + прогноз + конус)
     и текст простыми словами;
  2) тот же прогноз вшит в сводку ИИ-трейдера перед КАЖДОЙ сделкой -
     теперь LLM видит не только прошлое, но и оценку будущего;
- **СОВЕТ ИИ В ОТЧЁТЕ СКАНЕРА**: список кандидатов по-прежнему
  отсортирован по «хорошести» сигнала, но в конце добавлено короткое
  резюме ИИ простыми словами - что советует покупать и в каких
  количествах (лотов), без сложных терминов. Разбор ответа ИИ стал
  устойчивее: даже битый JSON больше не убивает комментарии;
- **/stats и /positions по всем бумагам**: статистика и график строятся по
  ВСЕМ бумагам под управлением (движок + позиции), а не только по тикерам
  из .env; у позиций, чья живая цена недоступна, результат считается по
  последней сохранённой точке - строка «сейчас ... → +X%» больше не
  пропадает;
- **промпт ИИ-трейдера расширен** знаниями из открытых трейдер-скиллов
  (tradermonty/claude-trading-skills: теханализ, риск на сделку 1-2%,
  дисциплина «нет плана - нет сделки»; agiprolabs/claude-trading-skills:
  z-score и half-life, EWMA-волатильность, лестница тейков с безубытком,
  трейлинг, временной стоп, выход по RSI>70/MACD).

Новое в v1.7.1:
- **АВТОПОКУПКА СО СКАНЕРА (главное)**: бот теперь может САМ купить лучшего
  кандидата из отчёта сканера - без нажатия кнопок. После каждого скана
  кандидаты прогоняются через ПОЛНЫЙ путь входа движка: порог сигнала,
  анти-погоня, новости, вердикт ИИ, кулдаун, дневные лимиты, бюджет -
  не прошёл хотя бы один фильтр, остаётся только в отчёте. Лимит -
  SCAN_AUTO_BUY_PER_SCAN (по умолчанию 1) покупок за скан. Кандидат,
  купленный сам, добавляется под управление (watchlist), иначе у позиции
  не было бы выхода. Переключение в Telegram: **/autobuy** (on/off),
  в .env: `SCAN_AUTO_BUY=true/false`;
- **исправлен крах /help и /start** (`Bad Request: message is too long`):
  справка выросла до ~4.7-7.3 тыс. символов, а Telegram не принимает
  сообщения длиннее 4096. Теперь любой длинный текст (справка, /start,
  /status, /memory, уведомления движка) режется на части по строкам
  (split_message), кнопки вешаются на первую/последнюю часть;
- **понятные кнопки сканера**: «Веду ТИКЕР» переименована в
  **«🤖 Торгуй ТИКЕР»** (отдать боту под автоторговлю), «Купить» уточнена до
  **«🛒 Купить ТИКЕР (1 лот)»**; в клавиатуру добавлена кнопка /autobuy;
- сделки движка (включая автопокупку) идут под общим `_trade_lock` с
  повторной проверкой позиции под замком - цикл, сканер и ручные /buy /sell
  физически не могут купить одну бумагу дважды.

Новое в v1.7.0:
- **ИСПРАВЛЕН ГЛАВНЫЙ БАГ СКАНЕРА**: живые поля LAST / LASTTOPREVPRICE /
  VALTODAY MOEX отдаёт в блоке **marketdata**, а не securities - раньше
  сканер читал их у securities, ISS молча выкидывал незнакомые колонки,
  обороты всегда были нулями, и бот писал «рынок не торгуется» даже в
  разгар торгового дня и никогда не находил кандидатов. Теперь снимок
  склеивает оба блока (проверено на живой бирже: 510 бумаг, 11+ млрд руб
  оборота, 38 бумаг проходят фильтр);
- **сообщение «торгов нет» честное и не спамит**: приходит только при
  реальных нулевых оборотах, с точным временем и днём недели, и не чаще
  раза в 3 часа (ручной /scan отвечает всегда);
- **утренний якорь**: с 10:00 до 13:00 МСК (MORNING_ANCHOR_UNTIL) бот не
  опирается на «ночной график» - средняя считается по основной сессии
  вчерашнего дня + сегодняшнему утру, а ИИ видит вчерашнюю динамику
  (включая отдельную цифру «как двигалось вчера утром»);
- **анти-погоня**: бот не покупает у локального максимума (цена ближе
  CHASE_GUARD_PCT% к максимуму окна) и когда отскок от минимума уже
  отыгран (CHASE_BOUNCE_PCT%) - именно так исчезают «покупки на хаю»
  (кейс LKOH);
- **радар разворота (защита прибыли)**: если прибыль дорастала до
  SURGE_SENSE_FROM_PCT% (по умолчанию 3%), бот продаёт при ПЕРВОМ намёке
  на разворот - затухание импульса, цена под средней, две свечи вниз,
  перегрев RSI/Боллинджера;
- **опрос чаще**: 300 -> 180 сек (POLL_INTERVAL_SEC);
- **скальп-режим /scalp**: сканер каждые 10 мин сам отбирает лучшие бумаги
  всего рынка (до SCALP_MAX_POSITIONS=10 одновременно), полные циклы
  каждые 5 мин, быстрая охрана позиций каждые 2.5 мин, стопы короче
  (−2%), фиксация туже (тиры с +2%), бюджет на бумагу - равная доля
  лимита вложенности. Выключается тем же /scalp;
- **кнопки в Telegram**: reply-клавиатура с командами, синее меню команд
  (set_my_commands), inline-кнопки «Купить»/«Торгуй» в отчётах сканера и
  «Продать» в /positions;
- **база знаний трейдера в промпте**: distilled правила классики
  (не гнаться за ценой, утренние движения живут по своим законам,
  фиксировать прибыль при затухании импульса и т.д.).

Новое в v1.6.1 (исправление ночного поведения):

  (fail-open), а 30079 в цикле пишется WARNING-ом, а не ERROR.

Новое в v1.6.0:
- **сканер рынка**: каждые 10 минут бот просматривает почти весь рынок
  Мосбиржи (все ликвидные бумаги TQBR через открытый MOEX ISS + свечи через

## 2. Стратегия (v1.7.0)

**Гибрид "индикаторы + трейдер-LLM"**, два независимых регулятора частоты:

- **Активность** `/set_activity 0..100` - масштаб времени: какая рабочая
  средняя и на каких свечах работает движок (100 = средняя ~1 ч на 5-минутных
  свечах, 50 = ~5 ч на 15-минутных, 0 = 24 ч на часовых). Отдельно задаёт,
  какой отрезок графика видит ИИ и как часто пересматривает позиции.
- **Агрессивность** `/set_aggressiveness 0..100` - решительность: порог
  сигнала score и требуемая уверенность LLM (чем выше, тем чаще покупает).

**Вход**: score индикаторов (SMA, RSI-14, MACD, Боллинджер, изменения за
1/6/24 ч) >= порога, сентимент новостей выше допуска, ИИ-трейдер сказал
`buy` с достаточной уверенностью. Затем страховки частоты: кулдаун между
покупками одной бумаги, дневной лимит покупок, потолок общей вложенности
(`/set_invested`), лимит на одну сделку (`MAX_POSITION_PCT`).

**Дисциплина входа (v1.7.0)**:
- **утренний якорь**: с 10:00 до `MORNING_ANCHOR_UNTIL`:00 МСК средняя
  считается по основной сессии вчерашнего дня + сегодняшнему утру
  (вечерняя сессия и ночные пустоты выбрасываются), а ИИ получает
  вчерашнее закрытие, гэп открытия и отдельную цифру «как двигалось
  вчера утром»;
- **анти-погоня**: вход запрещён, если цена ближе `CHASE_GUARD_PCT`%
  (0.5%) к максимуму локального окна или отскок от минимума уже отыграл
  `CHASE_BOUNCE_PCT`% (1.2%) - так не покупают «на хаю».

**Лестница выходов** (по позиции, приоритет сверху вниз):
1. аварийный стоп (глубже обычного стоп-лосса в `HARD_SL_MULT` раз) - сразу;
2. тейк-профит (+`TAKE_PROFIT_PCT`%) - фиксация прибыли;
3. **умная фиксация прибыли (`HARVEST_TIERS`, v1.6.0)**: если пик прибыли
   дорос до тира, допустимый откат от пика резко сужается. По умолчанию
   `3:0.7, 5:0.4, 8:0.25`: пик ≥3% -> продаём при откате 0.7 п.п., пик ≥5% ->
   0.4 п.п., пик ≥8% -> всего 0.25 п.п. (пример: бумага выросла на +8.4%,
   чуть осела до +8.1% - продаём сразу, не дожидаясь большого отката).
   Вето ИИ здесь не работает - это защита заработанного;
4. трейлинг-стоп: после +`TRAILING_ACTIVATE_PCT`% продаёт при откате
   `TRAILING_DROP_PCT`% от максимума - рост не превращается в убыток;
5. стоп-лосс с подтверждением: цена ниже уровня `SL_CONFIRM_CYCLES` циклов;
   перед продажей бот спрашивает ИИ, не ложный ли прокол (вето только при
   уверенности >= `SL_VETO_CONFIDENCE`);
6. досрочная продажа по вердикту ИИ-трейдера (только в плюс
   `LLM_EARLY_SELL_MIN_PROFIT`%).

**Радар разворота (v1.7.0)**: если прибыль когда-то дорастала до
`SURGE_SENSE_FROM_PCT`% (3% в обычном режиме, 1.5% в скальпе), позиция
продаётся при ПЕРВОМ признаке разворота: MACD-гистограмма затухает, цена
ушла под рабочую среднюю, две свечи падения подряд, RSI >= 70, цена у
верхней полосы Боллинджера, последний час отрицательный. Работает только
в плюс - за убытками следят стопы.

**Скальп-режим (`/scalp`, v1.7.0)**: отдельный режим для многих мелких
сделок по всему рынку: сканер каждые `SCAN_INTERVAL_MIN` мин сам обновляет
список бумаг (до `SCALP_MAX_POSITIONS` = 10), полные циклы - каждые
`SCALP_POLL_SEC` (300), охрана позиций (только выходы) - каждые
`SCALP_EXIT_POLL_SEC` (150 сек): сделка закрывается, как только цена
перестала расти. Стопы/тиры скальпа: `SCALP_STOP_LOSS_PCT` (2%),
`SCALP_HARVEST_TIERS` (2:0.4, 3:0.25, 5:0.15), `SCALP_SURGE_FROM_PCT`
(1.5%). Бюджет на бумагу - равная доля лимита вложенности. При включении
`/scalp` лимит вложенности автоматически поднимается до 70% (если был
ниже) - владелец уведомляется.

> Совет: чтобы тиры 5%/8% вообще могли сработать, поднимите тейк-профит:
> `TAKE_PROFIT_PCT=8`..`10` в .env (по умолчанию 5% продаст раньше,
> чем пик дорастёт до верхних тиров).

**Сканер рынка** (`scanner.py`, v1.6.0): раз в `SCAN_INTERVAL_MIN` минут
(по умолчанию 10) - один открытый запрос к MOEX ISS (весь режим TQBR: цены,
изменение за день, обороты, без ключей) -> фильтр ликвидности (оборот ≥
`SCAN_MIN_TURNOVER_MLN` млн руб/день, цена ≥ `SCAN_MIN_PRICE`) -> пул для
глубокого анализа: топ-10 по обороту + 5 самых упавших + 5 самых выросших
(бумаги из watchlist и с открытыми позициями исключаются) -> по каждой бумаге
свечи 15 мин за ~26 ч и тот же индикаторный score, что у движка -> топ-6
кандидатов в Telegram: текст (цена, score, RSI, изменение, оборот,
вердикт ИИ одним общим запросом) + **2 фото графиков** (по 3 панели).
v1.7.1: сканер может и **купить сам** - лучших кандидатов до
`SCAN_AUTO_BUY_PER_SCAN` за скан (по умолчанию 1), каждый проходит полный
путь проверок движка (см. «Новое в v1.7.1»); переключение `/autobuy`.
Ручные варианты: купить сразу (`/buy` или кнопка «Купить ТИКЕР (1 лот)»)
или отдать боту под автоторговлю (`/watch` или кнопка «Торгуй ТИКЕР»).
Команда `/scan` запускает проход прямо сейчас.

**Ручные сделки** (v1.6.0): `/buy ТИКЕР ШТ` и `/sell ТИКЕР [ШТ]` выполняются
сразу, минуя сигналы и ИИ (это явное указание человека), но НЕ минуя деньги:
проверяются свободные средства, лимит на сделку (вручную разрешено максимум
2 таких лимита), общий лимит вложенности; количество задаётся в штуках и
пересчитывается в лоты. Купленное вручную берётся под полный присмотр
(стопы/тейк/фиксация работают как обычно). `/sell` без числа продаёт всё;
если у бота позиции нет - бумага продаётся с брокерского счёта; частичная
продажа поддерживается; полные закрытия записываются в память сделок.

**Watchlist на 6 бумаг**: список тикеров берётся из `TRADING_TICKERS` (.env,
до 6) и меняется на ходу: `/watch MTSS` - добавить (до `MAX_TICKERS=6`),
`/unwatch` - убрать (нельзя, пока открыта позиция), `/watchlist` - показать.
Список сохраняется в state.json и переживает рестарт.

**Обучение на ошибках** (`trade_memory.py`, `LEARNING=True`): каждая закрытая
сделка запоминается (цены, причина выхода, час входа, длительность, итог).
Из памяти движок берёт: паузу бумаге после 3 убытков подряд
(`LOSS_STREAK_PAUSE_H`), повышенный порог сигнала после 2 убытков, пропуск
"плохих часов" входа (в которых все сделки были в убыток), дневной лимит
убытка (`DAILY_LOSS_LIMIT_PCT` - после него новых покупок до завтра).
Уроки передаются и в промпт ИИ-трейдера. Смотреть: `/memory`, сбросить:
`/reset_memory`.

**Критичные правила памяти** (выполнены):
- тикеры (макс. 6 из `TRADING_TICKERS`/watchlist) обрабатываются **строго последовательно**
  в `for`-цикле; `asyncio.gather()` в коде **не используется вообще**;
- сканер тоже последовательный: 1 снимок рынка + до `SCAN_DEEP_N` бумаг по свечам за проход;
- без pandas/numpy - только stdlib + лёгкие SDK (matplotlib - только для картинок);
- `RotatingFileHandler`: 5 МБ x 3 файла (~20 МБ максимум на диске).

**Почему `t-tech-investments`, а не `tinkoff-investments`**: официальный SDK
Т-Инвестиций был переименован после ребрендинга Т-Банка. Он ставится с
официального индекса T-Bank - строка `--extra-index-url` уже прописана в
`requirements.txt`. Телеметрия SDK (Sentry/error-hub) отключена
monkey-patch в `tinkoff_client.py`: на VPS она только генерировала
SSL-ошибки и мусор в логе.

## 8. Расход лимитов (все - бесплатные)

- **Groq free**: при `openai/gpt-oss-20b` - ~30 запросов/мин и ~1000
  запросов/сутки; бот тратит: вердикты трейдера с кэшем 10-30 мин, сентимент
  <= 6 раз/6 ч на тикер, часовой аудит, 1 запрос сканера на проход -
  запас многократный. Модель задаётся `GROQ_MODEL`.
- **T-Invest API**: ~4-6 запросов на тикер за цикл (по умолчанию 5 мин) +
  ~40 запросов за проход сканера (1 раз в 10 мин); локальный rate-limiter
  `RATE_LIMIT_RPM` общий для всего бота + retry при `RESOURCE_EXHAUSTED`.
- **MOEX ISS** (сканер): открытый API без ключей и лимитов, 1 запрос за проход.

## 9. Диагностика

```bash
tail -n 100 logs/bot.log        # основной лог (ротация 5 МБ x 3)
venv/bin/python cleanup.py      # ручная чистка старых логов
```

| Симптом | Причина/решение |
|---|---|
| `ОШИБКА КОНФИГУРАЦИИ` на старте | Не заполнен .env - список в сообщении |
| `TypeError: ... unexpected keyword argument` | Файлы разных версий смешаны - обновите ВСЕ .py из одного коммита |
| `MOEX ISS: HTTP 4xx/5xx` в логе | Сайт биржи моргнул - сканер пропустит проход и попробует в следующий раз |
| Сканер присылает мало кандидатов | Строгие фильтры: снизьте `SCAN_MIN_TURNOVER_MLN`/`SCAN_MIN_PRICE` или `SCAN_DEEP_N` |
| Сканер пишет «торгов нет» днём | v1.7.0 исправлено (обороты читались не из того блока ISS). Убедитесь, что задеплоен v1.7.0; проверьте `/scan` - сообщение теперь показывает точное время и день |
| `Bad Request: message is too long` в логе | v1.7.1 исправлено: длинные тексты режутся на части. Если видите - значит на сервере ещё старая версия |
| Бот купил бумагу без команды | Скорее всего это автопокупка сканера (сообщение «🤖 Автопокупка по итогам скана…»). Не нравится - `/autobuy off` |
| Бот покупает слишком часто сам | Уменьшите `SCAN_AUTO_BUY_PER_SCAN` (1-5) или выключите `/autobuy off`; дневной потолок покупок - `MAX_BUYS_PER_DAY` |
| Каждая строка лога повторяется дважды | stdout перенаправлен в logs/bot.log - перенаправьте в logs/stdout.log |
| `SDK Т-Инвестиций не установлен` | Не отработал pip install (проверьте extra-index-url) |
| Бот молчит в Telegram | Проверьте TELEGRAM_ADMIN_ID; при блокировке хостером - TELEGRAM_API_BASE |
| Groq RateLimit в логах | Нормально: бот ждёт по retry-after и повторяет |
