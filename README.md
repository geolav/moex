# MOEX Trading Bot v1.6.1 (T-Invest API + Groq AI + Telegram)

Production-ready торговый бот для Московской биржи, спроектированный под VPS
с **1 ГБ ОЗУ** и **15 ГБ диска**. Работает через официальный T-Invest API,
использует **бесплатный** Groq API (трейдер-LLM, сентимент новостей, аудит
логов, вердикты сканера) и управляется из Telegram.

Новое в v1.6.1 (исправление ночного поведения):
- **движок и сканер узнали о закрытой сессии**: ночью и в выходные песочница
  отклоняет заявки с `INVALID_ARGUMENT 30079` (официальное значение -
  "instrument is not available for trading"). Теперь перед циклом и сделками
  проверяется торговый статус бумаги (GetTradingStatus): вне сессии движок
  не дёргает ни цены, ни свечи, ни LLM (экономия квоты Groq), а ручные
  `/buy` и `/sell` объясняют, что рынок закрыт, и просят повторить в
  торговое время (осн. сессия 10:00-18:40 МСК, вечерняя 19:05-23:50);
- **сканер ночью не пугает пустыми отчётами**: если на ISS обороты всех
  бумаг обнулены, приходит короткое «рынок не торгуется - поищу после
  открытия» вместо «0 прошло фильтр»;
- если статус всё же не удалось получить, бот работает по-старому
  (fail-open), а 30079 в цикле пишется WARNING-ом, а не ERROR.

Новое в v1.6.0:
- **сканер рынка**: каждые 10 минут бот просматривает почти весь рынок
  Мосбиржи (все ликвидные бумаги TQBR через открытый MOEX ISS + свечи через
  T-Invest API) и присылает топ-6 кандидатов на покупку: текст + 2 фото
  графиков (по 3 графика на фото) + короткий вердикт ИИ;
- **до 6 бумаг под управлением** (было 3-5): `TRADING_TICKERS` в .env или
  добавление на ходу командой `/watch` (сохраняется в state.json);
- **ручные сделки из Telegram**: `/buy SBER 100` и `/sell GAZP 30`
  (штуки, пересчёт в лоты автоматический; продажа со счёта работает и для
  бумаг, купленных вне бота);
- **умная фиксация прибыли**: чем выше пик прибыли, тем меньший откат терпит
  бот - при сильном росте продаёт уже при крошечном падении (`HARVEST_TIERS`).

> Дисклеймер: алгоритмическая торговля - это риск. Бот - инструмент, а не
> гарантия прибыли. Первые недели держите его ТОЛЬКО в песочнице.

## 1. Архитектура

```
moex_trading_bot/
├── main.py              # точка входа: логирование, запуск всех задач, graceful shutdown
├── config.py            # конфиг из .env + StateStore (state.json: флаги, позиции, watchlist, история цен)
├── tinkoff_client.py    # T-Invest API: песочница/реал, цены, свечи, ордера, вселенная TQBR, снимок MOEX ISS
├── indicators.py        # "технический аналитик" без LLM: SMA/RSI/MACD/Боллинджер -> score
├── ai_analyst.py        # Groq: трейдер-LLM, сентимент, аудит логов, ответы, вердикты сканера
├── trading_engine.py    # гибридная стратегия + лестница выходов + ручные сделки + watchlist
├── scanner.py           # сканер рынка каждые SCAN_INTERVAL_MIN мин: топ кандидатов на покупку
├── charts.py            # групповые графики: 3 панели = 1 фото (сканер, /charts)
├── trade_memory.py      # память сделок: каждая закрытая сделка -> уроки (винрейт, серии убытков)
├── ai_auditor.py        # каждый час: последние N строк лога -> Groq -> вердикт в Telegram
├── telegram_bot.py      # команды: /start /status /buy /sell /charts /scan /watch /memory и др.
├── cleanup.py           # чистка старых логов (диск 15 ГБ не переполнится)
├── dry_run_test.py      # самопроверка на моках: python dry_run_test.py
├── requirements.txt
├── .env.example         # шаблон окружения -> копируем в .env
├── trading_bot.service  # systemd unit (автозапуск + авторестарт + MemoryMax)
└── logs/                # bot.log (ротация 5 МБ x 3 файла)
```

## 2. Стратегия (v1.6.1)

**Гибрид "индикаторы + трейдер-LLM"**, два независимых регулятора частоты:

- **Активность** `/set_activity 0..100` - масштаб времени: какая рабочая
  средняя и на каких свечах работает движок (100 = средняя ~1 ч на 5-минутных
  свечах, 50 = ~5 ч на 15-минутных, 0 = 24 ч на часовых). Отдельно задаёт,
  какой отрезок графика видит ИИ и как часто пересматривает позиции.
- **Агрессивность** `/set_aggressiveness 0..100` - решительность: порог
  сигнала score и требуемая уверенность LLM (чем выше, тем чаще покупает).

**Вход**: score индикаторов (SMA, RSI-14, MACD, Боллинджер, изменения за
1/6/24 ч) >= порога, сентимент новостей выше допуска, ИИ-трейдер сказал
`buy` с достаточной уверенностью. Затем страховки частоты: кулдаун между
покупками одной бумаги, дневной лимит покупок, потолок общей вложенности
(`/set_invested`), лимит на одну сделку (`MAX_POSITION_PCT`).

**Лестница выходов** (по позиции, приоритет сверху вниз):
1. аварийный стоп (глубже обычного стоп-лосса в `HARD_SL_MULT` раз) - сразу;
2. тейк-профит (+`TAKE_PROFIT_PCT`%) - фиксация прибыли;
3. **умная фиксация прибыли (`HARVEST_TIERS`, v1.6.0)**: если пик прибыли
   дорос до тира, допустимый откат от пика резко сужается. По умолчанию
   `3:0.7, 5:0.4, 8:0.25`: пик ≥3% -> продаём при откате 0.7 п.п., пик ≥5% ->
   0.4 п.п., пик ≥8% -> всего 0.25 п.п. (пример: бумага выросла на +8.4%,
   чуть осела до +8.1% - продаём сразу, не дожидаясь большого отката).
   Вето ИИ здесь не работает - это защита заработанного;
4. трейлинг-стоп: после +`TRAILING_ACTIVATE_PCT`% продаёт при откате
   `TRAILING_DROP_PCT`% от максимума - рост не превращается в убыток;
5. стоп-лосс с подтверждением: цена ниже уровня `SL_CONFIRM_CYCLES` циклов;
   перед продажей бот спрашивает ИИ, не ложный ли прокол (вето только при
   уверенности >= `SL_VETO_CONFIDENCE`);
6. досрочная продажа по вердикту ИИ-трейдера (только в плюс
   `LLM_EARLY_SELL_MIN_PROFIT`%).

> Совет: чтобы тиры 5%/8% вообще могли сработать, поднимите тейк-профит:
> `TAKE_PROFIT_PCT=8`..`10` в .env (по умолчанию 5% продаст раньше,
> чем пик дорастёт до верхних тиров).

**Сканер рынка** (`scanner.py`, v1.6.0): раз в `SCAN_INTERVAL_MIN` минут
(по умолчанию 10) - один открытый запрос к MOEX ISS (весь режим TQBR: цены,
изменение за день, обороты, без ключей) -> фильтр ликвидности (оборот ≥
`SCAN_MIN_TURNOVER_MLN` млн руб/день, цена ≥ `SCAN_MIN_PRICE`) -> пул для
глубокого анализа: топ-10 по обороту + 5 самых упавших + 5 самых выросших
(бумаги из watchlist и с открытыми позициями исключаются) -> по каждой бумаге
свечи 15 мин за ~26 ч и тот же индикаторный score, что у движка -> топ-6
кандидатов в Telegram: текст (цена, score, RSI, изменение, оборот,
вердикт ИИ одним общим запросом) + **2 фото графиков** (по 3 панели).
Сканер НЕ покупает сам: кандидата можно купить сразу (`/buy`) или отдать боту
под автоторговлю (`/watch`). Команда `/scan` запускает проход прямо сейчас.

**Ручные сделки** (v1.6.0): `/buy ТИКЕР ШТ` и `/sell ТИКЕР [ШТ]` выполняются
сразу, минуя сигналы и ИИ (это явное указание человека), но НЕ минуя деньги:
проверяются свободные средства, лимит на сделку (вручную разрешено максимум
2 таких лимита), общий лимит вложенности; количество задаётся в штуках и
пересчитывается в лоты. Купленное вручную берётся под полный присмотр
(стопы/тейк/фиксация работают как обычно). `/sell` без числа продаёт всё;
если у бота позиции нет - бумага продаётся с брокерского счёта; частичная
продажа поддерживается; полные закрытия записываются в память сделок.

**Watchlist на 6 бумаг**: список тикеров берётся из `TRADING_TICKERS` (.env,
до 6) и меняется на ходу: `/watch MTSS` - добавить (до `MAX_TICKERS=6`),
`/unwatch` - убрать (нельзя, пока открыта позиция), `/watchlist` - показать.
Список сохраняется в state.json и переживает рестарт.

**Обучение на ошибках** (`trade_memory.py`, `LEARNING=True`): каждая закрытая
сделка запоминается (цены, причина выхода, час входа, длительность, итог).
Из памяти движок берёт: паузу бумаге после 3 убытков подряд
(`LOSS_STREAK_PAUSE_H`), повышенный порог сигнала после 2 убытков, пропуск
"плохих часов" входа (в которых все сделки были в убыток), дневной лимит
убытка (`DAILY_LOSS_LIMIT_PCT` - после него новых покупок до завтра).
Уроки передаются и в промпт ИИ-трейдера. Смотреть: `/memory`, сбросить:
`/reset_memory`.

**Критичные правила памяти** (выполнены):
- тикеры (макс. 6 из `TRADING_TICKERS`/watchlist) обрабатываются **строго последовательно**
  в `for`-цикле; `asyncio.gather()` в коде **не используется вообще**;
- сканер тоже последовательный: 1 снимок рынка + до `SCAN_DEEP_N` бумаг по свечам за проход;
- без pandas/numpy - только stdlib + лёгкие SDK (matplotlib - только для картинок);
- `RotatingFileHandler`: 5 МБ x 3 файла (~20 МБ максимум на диске).

**Почему `t-tech-investments`, а не `tinkoff-investments`**: официальный SDK
Т-Инвестиций был переименован после ребрендинга Т-Банка. Он ставится с
официального индекса T-Bank - строка `--extra-index-url` уже прописана в
`requirements.txt`. Телеметрия SDK (Sentry/error-hub) отключена
monkey-patch в `tinkoff_client.py`: на VPS она только генерировала
SSL-ошибки и мусор в логе.

## 3. Установка на VPS (Ubuntu 22.04/24.04)

```bash
sudo apt update && sudo apt install -y python3-venv python3-pip git
# Код: git clone https://github.com/<ваш>/moex.git /opt/trading_bot
cd /opt/trading_bot
python3 -m venv venv
venv/bin/pip install --upgrade pip
venv/bin/pip install -r requirements.txt
venv/bin/python dry_run_test.py   # проверка логики без токенов
```

## 4. Настройка .env

```bash
cp .env.example .env && nano .env && chmod 600 .env
```

| Переменная | Где взять |
|---|---|
| `TINKOFF_SANDBOX_TOKEN` | Т-Инвестиции -> Профиль -> Настройки -> токен песочницы |
| `TINKOFF_TOKEN` | Там же, токен реального счёта (пока можно пустым) |
| `GROQ_API_KEY` | https://console.groq.com/keys (без карты) |
| `TELEGRAM_BOT_TOKEN` | @BotFather -> /newbot |
| `TELEGRAM_ADMIN_ID` | @userinfobot -> ваш числовой ID |
| `TELEGRAM_API_BASE` | Если api.telegram.org недоступен с VPS - URL реверс-прокси (Cloudflare Worker) |

Если api.telegram.org недоступен с VPS (блокировка хостера), бот ходит через
прокси: задайте `TELEGRAM_API_BASE=https://<ваш-worker>.workers.dev`.

## 5. Запуск

Вариант А - systemd (рекомендуется):
```bash
sudo cp trading_bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now trading_bot
journalctl -u trading_bot -f
```

Вариант Б - nohup вручную. ВАЖНО: не перенаправляйте stdout в `logs/bot.log` -
основной лог уже пишется RotatingFileHandler'ом, иначе каждая строка в файле
будет задвоена (и ИИ-аудитор будет читать половину полезных строк впустую):
```bash
nohup venv/bin/python main.py >> logs/stdout.log 2>&1 &
```

После старта в Telegram приходит приветствие; `/toggle_trading` включает
автотрейдинг.

## 6. Обновление версии (git-процесс)

Ноутбук -> GitHub -> сервер:
```bash
# на ноутбуке: заменить файлы, затем
git add -A && git commit -m "v1.6.0" && git push
# на сервере:
cd /opt/trading_bot && git pull --rebase
pkill -f "python.*main.py"; sleep 3
nohup venv/bin/python main.py >> logs/stdout.log 2>&1 &
```
Заменять нужно ВСЕ .py файлы сразу: модули связаны контрактами
(например, `main.py` передаёт `AppContext(memory=..., scanner=...)`), и набор
из разных версий падает при старте с `TypeError`.

**Обновление с v1.5.0 на v1.6.0 - чек-лист:**
1. Все .py из одного коммита (включая новые `scanner.py` и `charts.py`);
2. `venv/bin/pip install -r requirements.txt` - matplotlib уже был нужен для
   /stats, новых зависимостей нет;
3. В .env: поднять `TRADING_TICKERS` до 6 бумаг (например,
   `SBER,GAZP,LKOH,GMKN,ROSN,MTSS`) и, чтобы умная фиксация раскрывалась,
   `TAKE_PROFIT_PCT=8`; при желании - `HARVEST_TIERS=3.0:0.7,5.0:0.4,8.0:0.25`;
4. Перезапустить; в баннере должно быть "Сканер рынка: вкл (каждые 10 мин)".
   Первые 6 тикеров можно и не менять в .env - добавьте нужные через `/watch`.

## 7. Команды Telegram

| Команда | Действие |
|---|---|
| `/start` | Сводный статус простыми словами + справка |
| `/status` | Деньги, позиции, последние события, настройки, память сделок |
| `/positions` | Открытые позиции и их текущий результат по каждой |
| `/stats [часов]` | Статистика и график за 1-48 ч (по умолчанию 6) |
| `/charts [часов]` | Графики всех бумаг под управлением: 2 фото по 3 графика |
| `/scan` | Сканер рынка прямо сейчас: топ кандидатов + 2 фото |
| `/buy SBER 100` | Ручная покупка (штуки; обходит сигналы ИИ, не обходит деньги) |
| `/sell GAZP 30` | Ручная продажа (без числа - продать всё; работает и для бумаг вне бота) |
| `/watchlist` | Бумаги под автоматической торговлей (до 6) |
| `/watch MTSS` | Добавить бумагу под управление |
| `/unwatch MTSS` | Убрать бумагу (нельзя при открытой позиции) |
| `/ask вопрос` | Короткий вопрос ИИ-трейдеру (сводка собирается автоматически) |
| `/memory` | Что бот выучил из сделок: винрейт, уроки, плохие часы |
| `/reset_memory` | Забыть всю память сделок |
| `/set_aggressiveness N` | Решительность 0-100 (порог сигнала, уверенность ИИ) |
| `/set_activity N` | Масштаб времени 0-100 (средняя 24 ч -> 1 ч, свечи 60 -> 5 мин) |
| `/set_invested N` | Потолок доли ВСЕХ денег в акциях, 5-100% |
| `/audit [строк]` | ИИ-проверка логов прямо сейчас (10-200 строк) |
| `/toggle_trading` | Вкл/выкл автоторговлю |
| `/toggle_sandbox` | Песочница <-> реал (в реал - только с `confirm`) |
| `/toggle_auditor` | Вкл/выкл часового ИИ-аудитора |
| `/shutdown` | Остановить бота (systemd поднимет заново) |
| `/help` | Справка + словарик терминов |

Команды принимает только `TELEGRAM_ADMIN_ID`; остальных бот молча игнорирует.

## 8. Расход лимитов (все - бесплатные)

- **Groq free**: при `openai/gpt-oss-20b` - ~30 запросов/мин и ~1000
  запросов/сутки; бот тратит: вердикты трейдера с кэшем 10-30 мин, сентимент
  <= 6 раз/6 ч на тикер, часовой аудит, 1 запрос сканера на проход -
  запас многократный. Модель задаётся `GROQ_MODEL`.
- **T-Invest API**: ~4-6 запросов на тикер за цикл (по умолчанию 5 мин) +
  ~40 запросов за проход сканера (1 раз в 10 мин); локальный rate-limiter
  `RATE_LIMIT_RPM` общий для всего бота + retry при `RESOURCE_EXHAUSTED`.
- **MOEX ISS** (сканер): открытый API без ключей и лимитов, 1 запрос за проход.

## 9. Диагностика

```bash
tail -n 100 logs/bot.log        # основной лог (ротация 5 МБ x 3)
venv/bin/python cleanup.py      # ручная чистка старых логов
```

| Симптом | Причина/решение |
|---|---|
| `ОШИБКА КОНФИГУРАЦИИ` на старте | Не заполнен .env - список в сообщении |
| `TypeError: ... unexpected keyword argument` | Файлы разных версий смешаны - обновите ВСЕ .py из одного коммита |
| `MOEX ISS: HTTP 4xx/5xx` в логе | Сайт биржи моргнул - сканер пропустит проход и попробует в следующий раз |
| Сканер присылает мало кандидатов | Строгие фильтры: снизьте `SCAN_MIN_TURNOVER_MLN`/`SCAN_MIN_PRICE` или `SCAN_DEEP_N` |
| Каждая строка лога повторяется дважды | stdout перенаправлен в logs/bot.log - перенаправьте в logs/stdout.log |
| `SDK Т-Инвестиций не установлен` | Не отработал pip install (проверьте extra-index-url) |
| Бот молчит в Telegram | Проверьте TELEGRAM_ADMIN_ID; при блокировке хостером - TELEGRAM_API_BASE |
| Groq RateLimit в логах | Нормально: бот ждёт по retry-after и повторяет |
