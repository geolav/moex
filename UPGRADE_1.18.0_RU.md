# Обновление до 1.18.0 — Learning Supervisor

## Важно

Архив восстановлен на основе доступной сборки 1.17.1 и changelog 1.17.2–1.17.4, а не снят с VPS. Устанавливай сначала только в sandbox. Он содержит код и `.env.example`, но не твои реальные `.env`, `state.json`, торговую историю и `venv`.

## 1. Сделай резервную копию на VPS

У тебя проект находится в `/root/trading_bot/moex`.

```bash
cd /root/trading_bot
cp -a moex "moex_backup_$(date +%Y%m%d_%H%M%S)"
```

Останови старый процесс бота штатно: через `/shutdown` в Telegram либо останови его тем же способом, которым запускаешь. Не удаляй backup.

## 2. Передай архив на VPS

На своём компьютере (в каталоге, где лежит ZIP):

```bash
scp MOEX_bot_v1_18_0_learning_supervisor.zip root@168.113.189.205:/root/
```

## 3. Обнови исходники на месте, сохранив рабочее окружение

На VPS распакуй архив и скопируй его содержимое поверх текущего проекта:

```bash
cd /root/trading_bot
unzip -q /root/MOEX_bot_v1_18_0_learning_supervisor.zip
cp -a /root/trading_bot/moex_1180_supervisor/. /root/trading_bot/moex/
```

Архив намеренно НЕ содержит `.env`, `state.json`, `data/`, `logs/`, `venv/` или `.venv/`. Поэтому копирование не затронет твои токены, позиции/состояние, уже накопленные данные, логи и установленный Python venv. Полная резервная копия старого `moex/` остаётся рядом.

Дальше все команды выполняй в исходной папке:

```bash
cd /root/trading_bot/moex
```

## 4. Обнови существующий `.env`

В конец `.env` добавь эти строки (не присылай файл с ключами и не замещай им весь `.env`):

```dotenv
SUPERVISOR_ENABLED=true
SUPERVISOR_INTERVAL_SEC=60
SUPERVISOR_LOOKAHEAD_SEC=300
SUPERVISOR_GROQ_ENABLED=true
SUPERVISOR_GROQ_MIN_INTERVAL_SEC=3600
SUPERVISOR_AUTO_TUNE=true
SUPERVISOR_TARGET_COST_MULTIPLE=1.25
SUPERVISOR_GENERATE_PATCHES=true
SCALP_PRICE_REST_REFRESH_SEC=2.5
SCALP_PRICE_STALE_SEC=2.5
```

Удали дубликаты этих переменных, если они уже есть выше: оставь по одному определению каждой. Существующие `GROQ_API_KEY`, `GROQ_MODEL`, T-Invest токены и торговые настройки оставь своими.

`SUPERVISOR_GROQ_ENABLED=true` использует тот же Groq API-ключ и общий лимит/бюджет, что и остальной бот. Никакого OpenCode и нового платного API не требуется.

## 5. Проверь существующий Python venv

В этой версии нет новых Python-зависимостей, поэтому используй сохранённый `venv` в `/root/trading_bot/moex`. Проверь, что Groq SDK доступен:

```bash
cd /root/trading_bot/moex
venv/bin/python -c "import groq; print('groq OK')"
```

Если импорт не проходит, установи зависимости штатным способом из `requirements.txt` (требуется доступ к PyPI):

```bash
venv/bin/pip install -r requirements.txt
```

## 6. Первый запуск — только sandbox

```bash
cd /root/trading_bot/moex
venv/bin/python -m py_compile *.py
venv/bin/python main.py
```

Убедись, что состояние счёта — sandbox и автоторговля включена только там, где ты её действительно проверяешь. Не включай реальный счёт в первый день проверки.

## 7. Как проверить, что всё заработало

В логе ожидай строки:

- `Learning Supervisor запущен` — наблюдатель включился;
- `Scalp REST price fallback: проверено цен ...` — пакетный резерв цен реально работает;
- `Scalp stream НЕ ГОТОВ: продолжаю локальный поиск по пакетному REST` — stream недоступен, но резервный price path продолжает обработку;
- `Scalp stream: цена свежая ... (stream=..., REST=...)` — видно, сколько бумаг получает цену каждым способом;
- `Supervisor shadow ...` — найден потенциально пропущенный сетап, но ордер не отправляется;
- `Supervisor: самообучение изменило learned_policy` — пороги изменены по размеченным независимым эпизодам;
- `Groq Supervisor обнаружил проблему` — Groq выдал инженерный диагноз;
- `Patch и отчёт в staging` — предложенное изменение сохранено в отдельной копии, рабочие файлы не изменены.

В Telegram вызови:

```text
/supervisor
```

Там будут свежесть цен stream/REST, реальные триггеры, теневые кандидаты, потенциальные пропуски, число покупок и закрытий, win-rate и net P&L.

Supervisor начинает собирать собственную базу после установки. Он не может восстановить все пропущенные внутрисекундные моменты за предыдущие 6 часов из старых логов, потому что в них нет полного ценового ряда. Для контрфактической проверки сначала накапливаются новые снимки, затем проходит горизонт оценки.

## 8. Где хранятся результаты

- `data/supervisor.sqlite3` — история наблюдений, сигналов, сделок и меток;
- `data/supervisor/learned_policy.json` — текущие адаптивные пороги;
- `data/supervisor/proposals/` — Groq-диагнозы, diff и результат тестов;
- `data/supervisor/staging/` — отдельная копия проекта для тестирования diff.

Не удаляй эти файлы, если хочешь сохранить обучение. Сделай их частью резервных копий.

## Ограничение безопасности

Supervisor может автоматически изменять только ограниченные пороги обнаружения ям. Groq может подготовить и проверить patch в staging, но не заменяет работающие `.py`-файлы и не отключает стопы/лимиты. Это сделано намеренно: правка торговой логики без проверки может резко увеличить убытки. После нескольких дней sandbox-наблюдения можно отдельно рассмотреть ручное принятие конкретного patch.

Ещё раз: 100 входов в день — это максимум, не обещание 100 покупок. Одновременно остаётся не более 8 позиций и прежний бюджет риска портфеля.
