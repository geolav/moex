# Обновление до v1.17.1

1. Остановите процесс/службу старого бота.
2. Сделайте резервные копии `.env`, `state.json`, `data/trade_memory.json` и `logs/`.
3. Распакуйте архив v1.17.1 поверх проекта, сохранив свои `.env`, `state.json`, `data/` и `logs/`. Не заменяйте `.env` файлом `.env.example`.
4. Запустите бота. В первой строке должно быть `MOEX Trading Bot v1.17.1 стартует`. Если видите `v1.15.0`, запускается другой каталог/копия проекта либо архив распакован не поверх того каталога.

## Что проверить в логах

При старте: `Локальный поиск микродон ВКЛ: окна 12/20/35/60/120/240 сек ... без Groq`.

Дальше примерно раз в минуту будет строка здоровья stream: `Scalp stream ЗДОРОВ: свежие цена+стакан ...`. Если появится `Scalp stream НЕ ГОТОВ`, новые микродоны в данный момент не сканируются; восстановите подключение/подписку.

Затем примерно раз в минуту на отслеживаемую бумагу будет одна из строк:
- `Микродно TICKER: локальный анализ выполнен ... сигнал не подтверждён: ...` — видно, почему дно не прошло фильтр.
- `Микрояма TICKER: масштаб ... score ...` — локальное дно найдено и отправлено на AI-очередь.

Для позиции единая проверка P&L: `/positions` и `Скальп-мониторинг TICKER` используют полный процент круга; порог цены должен совпадать с `entry_price * (1 + round_trip_cost_pct / 100)`. После закрытия итоговая оценка затрат и net P&L использует то же значение. Это оценка по тарифу/спреду/проскальзыванию, а не фактическая комиссия из биржевого отчёта.

## Groq и лимиты

Scalp пакет не чаще одного запроса за 4 минуты и максимум 3 кандидата; дневной token budget не меняется. Увеличен только completion ceiling с 320 до 1024, чтобы GPT-OSS успевал вернуть JSON. Поиск микродон остаётся локальным и токены не потребляет. Лимиты риска/количества позиций не повышены.
