# Обновление до v1.16.0

## Перед обновлением

1. Остановите работающий процесс бота.
2. Сделайте копию каталога проекта, особенно `.env`, `state.json`, `data/` и `logs/`.
3. Распакуйте содержимое архива v1.16.0 поверх кода проекта. Не заменяйте свой `.env` файлом `.env.example`.
4. Убедитесь, что в `.env` установлены ваши реальные токены и параметры счёта.

## Новые и важные параметры

```dotenv
# Резервный контроль всех открытых scalp-позиций, секунды (минимум 5).
SCALP_EXIT_POLL_SEC=10

# Синхронизация внешних покупок из приложения брокера, секунды.
SCALP_PORTFOLIO_SYNC_SEC=30

# Общий лимит периодического и потокового scalp AI batch.
SCALP_AI_MIN_REQUEST_INTERVAL_SEC=240

# Разрешить безопасный fallback-кандидат, если строгий shortlist пуст.
SCAN_EMPTY_SHORTLIST_FALLBACK=True

# Для фактического Groq-анализа должны быть включены оба параметра.
SCAN_LLM=True
LLM_DECISIONS_ENABLED=True
```

`SCALP_EXIT_POLL_SEC` применяется к резервной REST-проверке при недоступном потоке. Когда поток активен, открытая позиция дополнительно проверяется при каждом новом тике.

`SCALP_PORTFOLIO_SYNC_SEC` действует только в скальп-режиме. Новая покупка, сделанная прямо в приложении брокера, будет обнаружена после следующей синхронизации; позиция начнёт сопровождаться по доступным котировкам. Для внешней покупки бот не может восстановить точное время исполнения, поэтому таймер удержания начинается с момента обнаружения позиции.

`SCALP_STOP_COOLDOWN_MIN` оставлен как legacy-параметр для совместимости, но повторный скальп-вход после стопа больше не блокируется им. Обычный `SCALP_COOLDOWN_MIN` остаётся действующим.

## Проверка после запуска

- Убедитесь, что в логе периодического скана появляются строки `Groq отправлено ... кандидата(ов), валидных ответов ...`.
- Если AI-запрос пропущен из-за общего лимита, в отчёте должно быть указано, что валидного ответа в этом цикле нет; это не равнозначно HOLD.
- Для потокового режима ожидаются строки синхронизации внешних позиций, если в брокерском портфеле есть незарегистрированные акции.
- Сравните `/charts` и `/stats`: в недавней истории открытой позиции должны появиться более частые точки потока; старшая часть окна берётся из свечей MOEX.

Сначала проверьте логику на песочнице. Частые котировки и локальные сигналы не гарантируют, что следующая сделка будет прибыльной: фактическая цена исполнения, задержка потока, ликвидность и проскальзывание могут отличаться от расчётных.
