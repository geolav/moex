# CHANGELOG 1.18.0 — Learning Supervisor и резерв last-price

Дата: 2026-11-11

## Главное

Добавлен независимый модуль `supervisor.py`. Он не открывает сделки и не заменяет риск-менеджмент. Его задача — измерять качество данных, регистрировать прохождение сигналов через торговый pipeline, искать потенциально пропущенные входы и учиться на последующем движении цены.

## 1. Критическое исправление потока цен

По журналу владельца last-price stream был свежим лишь для 1–4 из 15 бумаг, тогда как стакан приходил по 13–15 бумагам. При этом движок запускал детектор только при `scalp_feed_ready=True` и немедленно выходил при `False`.

Изменено:
- пакетный REST `GetLastPrices` вызывается независимо от готовности stream;
- все устаревшие FIGI запрашиваются одним пакетом, а не отдельным REST-вызовом для каждой бумаги;
- при отсутствии stream движок продолжает локальный анализ по REST-снимкам, если цена действительно свежая;
- источник `stream`/`rest` сохраняется отдельно;
- REST-снимок обновляет время проверки цены, но `price_seq` повышается только при изменении цены — одинаковые ответы API не запускают повторный детектор;
- в буфере хранятся временные REST-снимки, чтобы при следующем изменении видеть локальный путь цены.

Частота по умолчанию: один пакет раз в 2.5 секунды для всех stale-бумаг. Это резервный источник, он менее подробный, чем поток биржевых событий, и не восстанавливает пропущенные внутрисекундные сделки.

## 2. Supervisor и сбор доказательств

SQLite `data/supervisor.sqlite3` хранит:
- снимки цены, время свежести, источник цены, возраст стакана, spread и оценку полных издержек;
- реальные триггеры и теневые кандидаты более мягкого детектора;
- этап прохождения торгового pipeline: сигнал, очередь Groq, HOLD, отмена, попытка покупки, исполненная покупка;
- исполненные покупки/закрытия и net P&L закрытых позиций.

Повторяющиеся ошибки цены/входного pipeline записываются с троттлингом, чтобы SQLite не рос от тысяч одинаковых строк.

## 3. Проверка пропущенных покупок

Теневой детектор ничего не покупает. Он сохраняет потенциальный локальный разворот, который не прошёл обычный порог. Через `SUPERVISOR_LOOKAHEAD_SEC` (по умолчанию 300 секунд) Supervisor проверяет последующие сохранённые цены:
- была ли достигнута цель, превышающая полные расходы;
- был ли достигнут стоп раньше цели;
- не было ли ни одного касания.

Только теневые сигналы и реальные сигналы, которые не привели к покупке, могут считаться потенциально пропущенными. Это контрфактическая оценка на сохранённых снимках, а не доказательство того, что сделка гарантированно исполнилась бы по этой цене. Пропуски из прошлого, до установки 1.18.0, автоматически восстановить нельзя: в старых логах нет полного тикового ряда.

## 4. Ограниченное самообучение

После минимум 20 независимых размеченных эпизодов за 7 дней Supervisor может скорректировать только:
- `dip_min_score` в пределах 42–60;
- `dip_min_drop_pct` в пределах 0.005–0.05%.

Если реальные теневые эпизоды чаще достигают net-цели раньше стопа — пороги немного смягчаются. Если чаще проигрывают — ужесточаются. Одни и те же размеченные sample ID не используются для повторного шага обучения. Параметры рисков, комиссии, стопы, дневная потеря, число открытых позиций и размер позиции не меняются.

Это online-калибровка порогов на собственных наблюдениях, а не fine-tuning весов нейросети.

## 5. Groq как инженер-аудитор

Groq вызывается только при выявленной проблеме: низкое покрытие свежими ценами, несколько прибыльных теневых пропусков, серия убыточных закрытий или активный сбор данных без триггеров. По умолчанию не чаще одного запроса в час; запрос использует общий Groq-бюджет торгового приложения.

В запрос передаются метрики, недавние pipeline-события, теневые сделки, причины отказов и небольшой отфильтрованный хвост лога с редактированием типовых секретов.

Если Groq считает, что требуется изменение кода, он может создать unified diff только для разрешённого файла из allowlist. Patch копируется в отдельную staging-копию проекта, проверяется `git apply --check`, `compileall` и регрессионными тестами. **Рабочие файлы автоматически не перезаписываются**: торговый код, стопы и лимиты не должны изменяться без человеческой проверки. Локальные ограниченные пороги при этом обновляются автоматически.

## 6. Telegram

Добавлена команда `/supervisor`: свежесть stream/REST цены, число анализов/сигналов/теневых кандидатов, потенциальные пропуски, покупки/закрытия, win-rate, net P&L и текущие адаптивные пороги.

## 7. Параллельные позиции и риск

Сохранены прежние ограничения: не более 8 одновременно открытых scalp-позиций, риск 0.05% equity на позицию и общий бюджет риска портфеля 0.40% (если не переопределён существующим `.env`). Дневной лимит 100 — это потолок, не цель. Supervisor не принуждает к сделкам и не отключает риск-фильтры.
